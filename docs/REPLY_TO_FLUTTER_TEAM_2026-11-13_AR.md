## ١. السيرفر المباشر (القسم ١ في رسالتك)

خطأ `404` على `/governorates` سببه أن السيرفر يشغّل نسخة قديمة من الكود، مع أن هذا المسار موجود في المستودع منذ مدة. بعد رفع آخر نسخة من `main`، تُنفَّذ الأوامر التالية على السيرفر من داخل مجلد المشروع:

```bash
php artisan migrate --force
php artisan db:seed --force                          # base data; safe to re-run, never resets passwords
php artisan db:seed --class=DemoDataSeeder --force   # test accounts + approved test ads
php artisan storage:link                             # only if not done before
php artisan optimize:clear
```

بعدها تعمل كل المسارات التي ذكرتها، ومنها `/governorates` و `/ads/{id}/similar` و `/my/ads/stats` و `/ads/{id}/mark-sold` و `/ads/{id}/relist` ومساري `/report` و `/device-tokens`.

**بيانات الاختبار (من `DemoDataSeeder`):**

| الحساب | رقم الهاتف | كلمة المرور |
|---|---|---|
| بائع (يملك ٦ إعلانات منشورة بالصور، منها اثنان مميّزان) | `0933000001` | `demo-pass-123` |
| مشترٍ (لتجربة المفضلة والمحادثات والتقييمات) | `0933000002` | `demo-pass-123` |

وهناك تغييران آخران على السيرفر:
- **الرابط الرئيسي `/` أصبح يعرض الموقع الإلكتروني العام لسمسار.** الواجهة البرمجية نفسها لم تتغير تحت `/api`. أما رسالة فحص الحالة القديمة بصيغة JSON فانتقلت إلى `/healthz`.
- **رسائل استعادة كلمة المرور تحتاج إعدادات البريد في ملف `.env` على السيرفر** (`MAIL_MAILER` و `MAIL_HOST` و `MAIL_PORT` و `MAIL_USERNAME` و `MAIL_PASSWORD` و `MAIL_FROM_ADDRESS`). يصلح لذلك بريد من Hostinger. بدون هذه الإعدادات يستجيب المسار بشكل طبيعي، لكن لا تُرسل أي رسالة.

## ٢. الرد على كل بند

| البند | الرد | ملاحظات |
|---|---|---|
| **S1** تحديد عدد الطلبات | ✅ تم | ١٢٠ طلبًا في الدقيقة لكل مستخدم (أو لكل IP لغير المسجّلين) على كل `/api`. تسجيل الدخول والتسجيل ونسيت كلمة المرور وإعادة التعيين: ٥ محاولات في الدقيقة لكل هاتف أو بريد مع الـ IP، و ٢٠ في الدقيقة لكل IP. عند التجاوز يُرجَع `429` مع ترويسة `Retry-After`. الاستعلام الدوري عن المحادثة كل ٣ إلى ٥ ثوانٍ بعيد جدًا عن الحد. |
| **S2** ظهور الهاتف والبريد | ✅ تم | الحقلان `phone` و `email` أصبحا **غير موجودين** (المفتاح نفسه محذوف، وليس `null`) لكل مستخدم ما عدا صاحب الحساب (والمدراء). رقم البائع يظهر فقط في الحقل `contact_phone` داخل تفاصيل الإعلان (انظر C7). |
| **S3** صيغة رقم الهاتف | ✅ تم | تُخزَّن الأرقام بصيغة `09XXXXXXXX`. التسجيل والدخول وإعادة التعيين تقبل أي كتابة شائعة: `+963 999 111 222` و `00963…` و `963…` و `999111222`، مع شرطات أو مسافات أو أرقام عربية. الأرقام غير السورية تُرجع `422` على الحقل `phone`. وحُوّلت أرقام الحسابات الموجودة إلى نفس الصيغة. |
| **S4** حالة الإعلانات في المفضلة | ✅ تم | `/favorites` يعرض فقط الإعلانات `approved` و `sold`. |
| **S5** قيمة `rating_count` الفارغة | ✅ تم | أصبحت دائمًا رقمًا صحيحًا. |
| **S6** كلمة مرور الإدارة | ⏳ ضمن خطوات التحديث | لا يمكن تأكيدها قبل تحديث السيرفر. من لديه صلاحية الدخول للسيرفر يسجّل الدخول في الموقع على `/login` برقم هاتف الإدارة، ثم يستخدم **تغيير كلمة المرور** من صفحة الحساب. |
| **M1** نسيت كلمة المرور | ✅ تم، **عبر البريد الإلكتروني** | `POST /auth/forgot-password {phone}` أو `{email}` يرسل رمزًا من ٦ أرقام، صالحًا لمدة ٣٠ دقيقة، إلى البريد المسجّل في الحساب. `POST /auth/reset-password {phone or email, code, password}` يعيّن كلمة المرور الجديدة **ويلغي كل الـ tokens**، فيجب تسجيل الدخول من جديد. الرد متطابق سواء كان الحساب موجودًا أم لا. الحسابات التي ليس لها بريد لا تستطيع استخدامه، فيرجى عرض عبارة "تواصل مع الدعم" في هذه الحالة. |
| **M2** التحقق برسالة SMS | ❌ ليس في v1 | يرجى إخفاء الشاشة، فهي تحتاج مزوّد رسائل SMS مدفوعًا. |
| **M3** تعديل الملف الشخصي والصورة | ✅ تم | أرسل `PUT/PATCH /auth/me` بصيغة JSON للحقول النصية. **أما الصورة فاستخدم `POST /auth/me` بصيغة multipart**، لأن PHP لا يقرأ محتوى multipart مع `PUT`. الحقول: `name, email, governorate_id, city_id, avatar, remove_avatar`. يُرجع المستخدم مع `governorate` و `city`. |
| **M4** تغيير كلمة المرور | ✅ تم | `POST /auth/change-password {current_password, password}`. الـ token الحالي يبقى صالحًا، ويُسجَّل الخروج من باقي الأجهزة. |
| **M5** حذف الحساب | ✅ تم | `DELETE /auth/me {password}`. يحذف إعلانات المستخدم ومفضلته وتقييماته والـ tokens. المحادثات **تبقى** عند الطرف الآخر، ويظهر فيها المستخدم باسم `"مستخدم محذوف"`. إرسال رسالة جديدة لمستخدم محذوف يُرجع `422`. ويصبح رقم الهاتف والبريد متاحين للتسجيل من جديد. |
| **M6** الملف العام للبائع | ✅ تم | `GET /users/{id}`: الاسم، الصورة، المحافظة، المدينة، التقييم، `created_at`، `active_ads_count`، `sold_ads_count`. المستخدم المحظور أو المحذوف يُرجع `404`. |
| **M7** إعلانات بائع معيّن | ✅ تم | `GET /ads?user_id={id}`. نفس شكل `/ads` ونفس الترقيم. |
| **M8** نظام المتابعة | ❌ ليس في v1 | يرجى إخفاء هذه الشاشات. |
| **M9** تعليم المحادثة كمقروءة | ✅ تم | `POST /conversations/{id}/read` يُرجع `{"data": {"marked": n}}`. قراءة الرسائل **لا** تعلّمها كمقروءة تلقائيًا. |
| **M10** عدد الإشعارات غير المقروءة | ✅ تم | `GET /notifications/unread-count` يُرجع `{"data": {"count": n}}`. |
| **M11** ملخص التقييمات | ✅ تم | `GET /users/{id}/ratings/summary` يُرجع `{"data": {"average", "count", "stars": {"5": n … "1": n}}}`. |
| **C1** الحقل `is_favorited` | ✅ تم | موجود في كل إعلان وفي كل مكان. **أرسل الـ bearer token حتى في المسارات العامة**، وإلا ستكون القيمة دائمًا `false`. |
| **C2** البائع في عناصر القوائم | ✅ تم | الحقل `user` (`id, name, avatar_url, rating_*`) موجود في كل إعلان في كل القوائم. |
| **C3** العلاقات في المفضلة وإعلاناتي | ✅ تم | `category` و `governorate` و `city` و `user` و `images` موجودة في كل القوائم. |
| **C4** موقع المستخدم | ✅ تم | `register` و `login` و `GET /auth/me` و `PUT /auth/me` تحتوي `governorate` و `city`. |
| **C5** معاينة المحادثة | ✅ تم | كل محادثة فيها `last_message {id, body, sender_id, created_at}` (أو `null`) و `unread_count`. |
| **C6** الاستعلام الدوري عن الرسائل | ✅ تم | `?after_id={id}` يُرجع فقط الرسائل الأحدث، من الأقدم للأحدث، **بدون ترقيم** (حتى ٢٠٠ رسالة)، وهو المناسب للاستعلام الدوري. `?order=desc` يُرجع الأحدث أولًا مع ترقيم. الطلب بدون أي معامل يعمل تمامًا كما كان. |
| **C7** خيارات نشر الإعلان | ✅ تم | `is_negotiable` و `address` و `allow_chat` (افتراضيًا true) و `allow_calls` (افتراضيًا true) و `hide_phone` (افتراضيًا false) تعمل عند الإنشاء والتعديل وتظهر في كل إعلان. تفاصيل الإعلان تضيف `contact_phone`: رقم البائع عندما يسمح بالاتصال ولا يخفي رقمه، **وللمستخدمين المسجّلين فقط**، وإلا فهو `null`. مع `allow_chat: false` يُرجع بدء محادثة جديدة `422`. تغيير مفاتيح التواصل الثلاثة وحدها **لا** يعيد الإعلان للمراجعة. |
| **C8** الدفع عبر شام كاش | ⏳ عند الجاهزية | ما زال يُرجع `501` لأننا ننتظر صلاحية الوصول لواجهة شام كاش. نخطط لإرجاع `{"data": {"checkout_url": "..."}}` كما اقترحت، وسنؤكد عند الانتهاء. |
| **C9** الإشعارات الفورية | ⏳ نحتاج معرّفات التطبيق | سننشئ مشروع Firebase ونرسل لك `google-services.json` و `GoogleService-Info.plist`. يرجى إرسال **اسم حزمة Android (package name)** و **معرّف iOS (bundle ID)**. |

## ٣. تغييرات قد تؤثر على كود كتبته مسبقًا

1. **المفتاحان `phone` و `email` لم يعودا موجودين للمستخدمين الآخرين.** استخدم `contact_phone` من `GET /ads/{id}` لزر الاتصال.
2. **التسجيل يرفض الأرقام غير السورية** ويُرجع `422` على الحقل `phone`.
3. **قد يظهر `429` الآن** على أي مسار. شاشة تسجيل الدخول هي المكان الذي قد يواجهه فيه المستخدم فعليًا.
4. **قراءة المحادثة لا تعلّمها كمقروءة.** استدعِ `POST /conversations/{id}/read` عند فتح شاشة المحادثة، وبعد وصول رسائل جديدة وهي مفتوحة.
5. **المستخدمون المحذوفون** يظهرون باسم `"مستخدم محذوف"` في المحادثات، وملفهم العام يُرجع `404`، وإرسال رسالة لهم يُرجع `422`.
6. **إعادة تعيين كلمة المرور تلغي كل الـ tokens**، فأعد المستخدم لشاشة تسجيل الدخول. أما تغيير كلمة المرور فيُبقي الـ token الحالي.
7. **رفع الصورة الشخصية يجب أن يكون عبر `POST /auth/me`** (multipart)، وليس `PUT`.
