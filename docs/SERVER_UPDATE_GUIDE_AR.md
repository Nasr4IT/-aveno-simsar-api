# دليل تحديث سيرفر سمسار (Semsar) — تحديث ١٣ نوفمبر ٢٠٢٦

**إعداد: Aveno Code**
**لمن هذا الدليل:** للشخص الذي رفع المشروع سابقًا على سيرفر Hostinger VPS باستخدام **FileZilla** ولوحة **CyberPanel** (OpenLiteSpeed).
**المدة المتوقعة:** حوالي ٣٠ إلى ٤٥ دقيقة.

---

## ما الذي سنفعله ولماذا؟

النسخة الموجودة حاليًا على السيرفر (`simsar-sy.com`) **قديمة**، ولذلك يظهر لفريق التطبيق خطأ 404 عند طلب بعض الروابط مثل
`/api/governorates`. النسخة الجديدة تحتوي على:

- **الموقع الإلكتروني العام** (نفس خدمات التطبيق، بالعربية والإنجليزية، مع الوضع الليلي).
- كل ما طلبه فريق التطبيق (Salamah): استعادة كلمة المرور، تعديل الملف الشخصي، حذف الحساب، تحسينات المحادثات، الحماية من
  محاولات الدخول المتكررة، وغيرها.

**هذا تحديث وليس تركيبًا جديدًا.** لن نُنشئ موقعًا جديدًا ولا قاعدة بيانات جديدة، ولن نلمس ملف الإعدادات `.env` ولا صور
المستخدمين. فقط نستبدل ملفات البرنامج بالنسخة الجديدة ثم ننفّذ بعض الأوامر.

### ماذا تحتاج؟

- [ ] ملف التحديث: **`semsar-upload-2026-11-13.zip`** (أرسله لك المطوّر).
- [ ] برنامج **FileZilla** وبيانات الاتصال بالسيرفر (نفس ما استخدمته في المرة الأولى).
- [ ] بيانات الدخول إلى لوحة **CyberPanel**.

### قاعدة مهمة قبل أن تبدأ

في كل الأوامر الموجودة في هذا الدليل، استبدل **`اسم-نطاقك`** بالاسم الحقيقي لنطاقك كما هو في CyberPanel (على الأغلب:
**`simsar-sy.com`**)، واستبدل **`اسم-مستخدم-النظام`** باسم المستخدم الظاهر بجانب موقعك في صفحة
**Websites ← List Websites** في CyberPanel (نفس ما استخدمته في المرة الأولى).

> ⚠️ **ممنوع حذف أو استبدال هذه الأشياء على السيرفر:**
> - ملف **`.env`** — فيه إعدادات السيرفر وكلمة مرور قاعدة البيانات.
> - مجلد **`storage`** — فيه صور الإعلانات التي رفعها المستخدمون.
> - مجلد **`vendor`** — سنحدّثه بأمر خاص في الخطوة ٥، وليس بالرفع.
>
> ملف التحديث **لا يحتوي** على أيٍّ من هذه الثلاثة، لذلك لن يستبدلها. فقط لا تحذفها أنت يدويًا.

## الخطوة ١ — أخذ نسخة احتياطية (لا تتخطّ هذه الخطوة)

إن حدث أي خطأ، هذه النسخة تسمح لنا بإرجاع كل شيء كما كان.

1. افتح لوحة **CyberPanel** في المتصفح وسجّل الدخول.
2. من القائمة الجانبية اختر **Backup ← Create Backup**.
3. اختر موقعك (`اسم-نطاقك`)، ثم اضغط **Create Backup**.
4. انتظر حتى تظهر رسالة نجاح. هذه النسخة تشمل ملفات الموقع **وقاعدة البيانات** معًا.

وكاحتياط إضافي، احفظ نسخة من ملف الإعدادات على جهازك:

5. افتح **FileZilla** واتصل بالسيرفر (من **File ← Site Manager** اختر "سيرفر سمسار" ثم **Connect**).
6. في جهة السيرفر (Remote site) انتقل إلى: `/home/اسم-نطاقك/backend/`.
7. ستجد ملفًا اسمه **`.env`**. اسحبه إلى جهة جهازك (Local site) لتحميل نسخة منه.

> إذا لم يظهر ملف `.env`: من قائمة FileZilla اختر **Server ← Force showing hidden files**، لأن الملفات التي تبدأ بنقطة تكون مخفية.

---

## الخطوة ٢ — رفع ملف التحديث

1. في FileZilla، تأكد أنك داخل المجلد `/home/اسم-نطاقك/backend/` في جهة السيرفر.
2. في جهة جهازك، تصفّح حتى تصل إلى ملف **`semsar-upload-2026-11-13.zip`**.
3. اسحب الملف وأفلته داخل جهة السيرفر (أو اضغط عليه بزر الفأرة الأيمن واختر **Upload**).
4. انتظر حتى يكتمل الرفع (حجمه حوالي ١٫٧ ميغابايت، يعني ثوانٍ قليلة).

---

## الخطوة ٣ — فتح الطرفية (Terminal)

1. ارجع إلى **CyberPanel**.
2. اختر **Websites ← List Websites**، وبجانب موقعك اضغط **Manage**.
3. افتح **Terminal** (أو **SSH Terminal**) — ستظهر النافذة السوداء نفسها التي استخدمتها في المرة الأولى.
4. انتقل إلى مجلد المشروع:

```bash
cd /home/اسم-نطاقك/backend
```

> **من الآن فصاعدًا، كل الأوامر في هذا الدليل تُنفَّذ وأنت داخل هذا المجلد.** إن أغلقت الطرفية وفتحتها مرة أخرى، أعد تنفيذ أمر `cd` هذا أولًا.

---

## الخطوة ٤ — فك ضغط التحديث فوق الملفات القديمة

هذا الأمر يفك ضغط الملف ويستبدل ملفات البرنامج القديمة بالجديدة تلقائيًا (الحرف `-o` معناه: "استبدل دون أن تسألني عن كل ملف"):

```bash
unzip -o semsar-upload-2026-11-13.zip
```

ستمر أمامك أسطر كثيرة تبدأ بكلمة `inflating` أو `extracting` — هذا طبيعي.

بعد الانتهاء، احذف ملف الـ ZIP لأننا لم نعد نحتاجه:

```bash
rm semsar-upload-2026-11-13.zip
```

---

## الخطوة ٥ — تحديث مكتبات المشروع

مكتبات المشروع (مجلد `vendor`) تغيّرت منذ النسخة الموجودة على السيرفر. هذا الأمر يحدّثها تلقائيًا:

```bash
composer install --no-dev --optimize-autoloader
```

انتظر دقيقة أو دقيقتين حتى يعود موجه الأوامر. إذا ظهرت كلمة **"Nothing to install"** فهذا يعني أنها محدّثة أصلًا، ولا مشكلة.

---

## الخطوة ٦ — تحديث قاعدة البيانات

نفّذ الأوامر التالية **واحدًا تلو الآخر**، وانتظر انتهاء كل أمر قبل الذي يليه:

**١) إضافة الجداول والأعمدة الجديدة** (لا يحذف أي بيانات موجودة):

```bash
php artisan migrate --force
```

يجب أن ترى قائمة بأسماء ملفات وبجانبها كلمة **DONE**. إن ظهرت عبارة **"Nothing to migrate"** فلا مشكلة.

**٢) التأكد من وجود البيانات الأساسية** (المحافظات والمدن والفئات). هذا الأمر آمن تمامًا: يضيف فقط ما هو ناقص، **ولا يغيّر
كلمة مرور حساب الإدارة**:

```bash
php artisan db:seed --force
```

**٣) إنشاء حسابات وإعلانات تجريبية** لفريق التطبيق حتى يختبر عليها (طلبها Salamah بالاسم):

```bash
php artisan db:seed --class=DemoDataSeeder --force
```

في النهاية يجب أن تظهر لك رسالة تحتوي على أرقام الحسابات التجريبية: `0933000001` و `0933000002`.

## الخطوة ٧ — الصلاحيات، وتنظيف الذاكرة المؤقتة، وإعادة التشغيل

الملفات الجديدة رُفعت باسم المستخدم root، لذلك نعيد صلاحيات الكتابة للمجلدين اللذين يحتاجهما المشروع:

```bash
chown -R اسم-مستخدم-النظام:اسم-مستخدم-النظام storage bootstrap/cache
chmod -R 775 storage bootstrap/cache
```

ربط مجلد الصور (إن ظهرت رسالة أن الرابط **"already exists"** فهذا طبيعي ولا مشكلة):

```bash
php artisan storage:link
```

مسح الذاكرة المؤقتة للإعدادات القديمة حتى يعمل المشروع بالنسخة الجديدة:

```bash
php artisan optimize:clear
```

إعادة تشغيل "عامل الطابور" (البرنامج الذي يرسل الإشعارات) حتى يستخدم الكود الجديد، ثم إعادة تشغيل خادم الويب:

```bash
systemctl restart semsar-queue
systemctl restart lsws
```

تأكّد أن عامل الطابور يعمل:

```bash
systemctl status semsar-queue
```

يجب أن ترى **active (running)** باللون الأخضر. اضغط حرف `q` للخروج من هذه الشاشة.

## الخطوة ٨ — تغيير كلمة مرور حساب الإدارة (ضروري جدًا)

كلمة المرور الافتراضية `change-me-now` مكتوبة داخل كود المشروع، أي أنها **ليست سرًا**. إن لم تكن قد غيّرتها من قبل:

1. افتح المتصفح واذهب إلى: **`https://اسم-نطاقك/login`**
2. سجّل الدخول برقم الهاتف **`0999999999`** وكلمة المرور الحالية (`change-me-now` إن لم تُغيَّر من قبل).
3. اضغط على **حسابي** في الأعلى، ثم انزل إلى قسم **تغيير كلمة المرور**.
4. اكتب كلمة المرور الحالية، ثم كلمة مرور جديدة قوية مرتين، واضغط **تغيير كلمة المرور**.
5. **أرسل كلمة المرور الجديدة لصاحب المشروع بطريقة آمنة** (ليس في مجموعة عامة).

> كلمة المرور هذه نفسها هي التي تُستخدم لدخول لوحة الإدارة على: `https://اسم-نطاقك/admin-panel/login`

## الخطوة ٩ — اختبار أن كل شيء يعمل

افتح هذه الروابط في المتصفح وتأكد من النتيجة:

| الرابط | النتيجة الصحيحة |
|---|---|
| `https://اسم-نطاقك/` | الصفحة الرئيسية للموقع، وفي أسفلها عبارة **Powered by AvenoCode** |
| `https://اسم-نطاقك/api/governorates` | نص بيانات يبدأ بـ `{"data":[` يحتوي أسماء المحافظات **(وليس 404)** |
| `https://اسم-نطاقك/api/ads` | نص بيانات يحتوي الإعلانات التجريبية |
| `https://اسم-نطاقك/admin-panel/login` | شاشة تسجيل دخول **Semsar Admin Panel** |
| `https://اسم-نطاقك/healthz` | `{"app":"...","status":"ok"}` |

جرّب أيضًا تسجيل الدخول في الموقع بالحساب التجريبي `0933000001` وكلمة المرور `demo-pass-123`.

**إذا نجحت كل الاختبارات: انتهى التحديث 🎉** أرسل لصاحب المشروع رسالة بذلك، حتى يُبلغ فريق التطبيق أن السيرفر أصبح جاهزًا.

## خطوة اختيارية — تفعيل إرسال البريد الإلكتروني (لاستعادة كلمة المرور)

ميزة **"نسيت كلمة المرور؟"** ترسل رمزًا إلى البريد الإلكتروني للمستخدم. بدون هذه الخطوة يعمل كل شيء آخر بشكل طبيعي، لكن
رسائل الرمز لن تصل.

1. أنشئ بريدًا إلكترونيًا للنطاق من لوحة Hostinger: **hPanel ← Emails**، مثلًا `no-reply@اسم-نطاقك`، واحفظ كلمة مروره.
2. في الطرفية افتح ملف الإعدادات:

```bash
nano .env
```

3. ابحث عن الأسطر التي تبدأ بـ `MAIL_` وعدّلها لتصبح هكذا (ضع البريد وكلمة مروره الحقيقيين):

```ini
MAIL_MAILER=smtp
MAIL_HOST=smtp.hostinger.com
MAIL_PORT=465
MAIL_USERNAME=no-reply@اسم-نطاقك
MAIL_PASSWORD=كلمة-مرور-البريد
MAIL_ENCRYPTION=ssl
MAIL_FROM_ADDRESS="no-reply@اسم-نطاقك"
```

4. احفظ واخرج: `Ctrl` + `O` ثم `Enter`، ثم `Ctrl` + `X`.
5. نفّذ هذين الأمرين حتى تُقرأ الإعدادات الجديدة:

```bash
php artisan optimize:clear
systemctl restart semsar-queue
```

6. للتجربة: افتح `https://اسم-نطاقك/forgot-password`، واكتب بريدًا إلكترونيًا مسجّلًا في حساب، ثم تأكد أن الرمز وصل.

## إذا واجهت مشكلة

| المشكلة | الحل |
|---|---|
| خطأ 500 أو صفحة بيضاء | نفّذ `tail -n 50 storage/logs/laravel.log` وأرسل الناتج (صورة شاشة) للمطوّر |
| `composer: command not found` | جرّب `/usr/local/bin/composer install --no-dev --optimize-autoloader`، وإن لم ينجح أبلغ المطوّر |
| خطأ `Permission denied` عند فتح الموقع | أعد تنفيذ أمرَي `chown` و `chmod` في الخطوة ٧ مع التأكد من اسم مستخدم النظام الصحيح |
| `/api/governorates` ما زال يعطي 404 | تأكد أنك فككت الضغط داخل المجلد `backend` نفسه (الخطوة ٤)، ثم نفّذ `php artisan optimize:clear` و `systemctl restart lsws` |
| الصور لا تظهر | نفّذ `php artisan storage:link` ثم أمرَي الصلاحيات في الخطوة ٧ |
| رسالة `Too Many Attempts` عند تسجيل الدخول | هذه حماية جديدة ضد التخمين: بعد ٥ محاولات خاطئة خلال دقيقة يجب الانتظار دقيقة واحدة. ليست عطلًا |
| أي شيء خرب ولم تعرف حله | **لا تحاول حلولًا عشوائية.** يمكن إرجاع كل شيء من النسخة الاحتياطية: **CyberPanel ← Backup ← Restore Backup**، ثم تواصل مع المطوّر |
